## 1. find_related_groups.py - Over-Aggressive Matching

**Issue:** Script was matching groups from different countries (e.g., German and American units with similar names) and hierarchically related organizations (e.g., "British Army" + "British Second Army").

**Root Cause:** The `_has_shared_context()` function checked if countries matched and added 0.4 to confidence, but it didn't prevent matching groups with different countries or hierarchical relationships.

**Fix 1 - Country Mismatch Check:** Added country mismatch check at the start of comparison logic:

```python
# Check 0: DIFFERENT countries - skip unless very high similarity
country1 = (group1.get("country_of_origin") or "").lower()
country2 = (group2.get("country_of_origin") or "").lower()
if country1 and country2 and country1 != country2:
    # Different countries - only match if name similarity is very high (90%+)
    similarity = _similarity_ratio(name1, name2)
    if similarity < 0.90:
        continue  # Skip this pair
    reasons.append(f"⚠️ Different countries ({country1} vs {country2}) but very high name similarity")
```

## 2. merge_related_groups.py - KeyError on MentionID

**Issue:** Script crashed with `KeyError: 'EventMentionID'` when merging groups.

**Root Cause:** The merge function was looking for `EventMentionID` field, but people groups use `MentionID` (from schema).

**Fix:** Updated merge function to handle both field name variations:

```python
# Before:
existing_mentions = {m["EventMentionID"] for m in primary.get("event_mentions", [])}

# After:
existing_mentions = {m.get("MentionID") or m.get("mention_id") for m in primary.get("event_mentions", [])}
```

**Handles:**
- ✅ `MentionID` (PascalCase - from schema)
- ✅ `mention_id` (snake_case - alternative)
- ✅ Missing field (returns None, filtered out)

**Files Modified:**
- `scripts/merge_related_groups.py` (lines 31-38)

**LLM verification automatically disabled if:**
- Grok client initialization fails
- API errors occur
- User prefers heuristic-only matching
