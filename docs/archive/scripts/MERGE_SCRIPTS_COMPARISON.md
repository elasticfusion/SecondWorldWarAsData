## merge_duplicate_people.py vs merge_related_groups.py

### ✅ Shared Features (Same Logic)

Both scripts have identical interactive workflow:

#### 1. Interactive Prompts
- ✅ `y` - Merge the group/cluster
- ✅ `n` - Stop processing
- ✅ `skip` - Skip this group, continue to next
- ✅ `exclude` - Add to exclusion list

#### 2. Selective Exclusion
- ✅ Prompt: "Enter numbers to exclude (comma-separated, or 'all')"
- ✅ Exclude specific items from group
- ✅ Option to merge remaining items after exclusion
- ✅ Prompt: "Merge remaining? (y/n)"

#### 3. Exclusion Persistence
- ✅ Loads existing exclusions on startup
- ✅ Saves new exclusions immediately
- ✅ Skips groups already in exclusion list

#### 4. Choose Primary
- ✅ Prompts which item to keep as primary
- ✅ Shows default based on data quality
- ✅ Allows user override

#### 5. Merge Logic
- ✅ Merges event mentions (deduplicates by MentionID)
- ✅ Merges alternate names
- ✅ Keeps primary file, deletes others
- ✅ Shows merge summary

## Key Differences

### Input Source

**merge_duplicate_people.py:**
- Reads: `output/people/duplicate_report.json`
- Generated by: `find_duplicate_people.py`
- Based on: Name similarity

**merge_related_groups.py:**
- Reads: `output/people_groups/related_groups_report.json`
- Generated by: `find_related_groups.py`
- Based on: Name similarity + hierarchy + shared context

### Exclusion File

**merge_duplicate_people.py:**
- Creates: `output/people/not_duplicates.json`
- Format: Array of PersonID arrays

**merge_related_groups.py:**
- Creates: `output/people_groups/not_related.json`
- Format: Object with exclusion pairs

### Entity Type

**merge_duplicate_people.py:**
- Merges: Individual people
- Fields: PersonID, name, biographical_profile, event_mentions

**merge_related_groups.py:**
- Merges: People groups (organizations, units)
- Fields: PeopleGroupID, group_name, alternate_names, event_mentions

## Code Structure Comparison

### Function Names

| merge_duplicate_people.py | merge_related_groups.py | Purpose |
|---------------------------|-------------------------|---------|
| `_get_user_action()` | `get_user_action()` | Get merge/skip/exclude choice |
| `_get_exclusion_indices()` | `get_exclusions_from_user()` | Select items to exclude |
| `_choose_primary()` | `get_primary_index()` | Choose primary record |
| `_merge_people()` | `merge_groups()` | Merge data |
| `_process_duplicate_group()` | `merge_related_cluster()` | Process one group |

### Logic Flow

Both follow identical pattern:

```
1. Load report file
2. Load existing exclusions
3. For each group:
   a. Show group details
   b. Check if excluded
   c. Get user action (merge/skip/exclude/stop)
   d. If exclude:
      - Get exclusion indices
      - Save exclusions
      - Prompt to merge remaining
   e. If merge:
      - Choose primary
      - Merge data
      - Delete duplicates
4. Show summary
```
